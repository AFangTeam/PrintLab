# 打印能力与首次验证

## 首版的设备适配

PrintLab 工作台可在未连接设备时启动。接入 Bambuddy 后提供状态、材料与打印历史。本候选版已扩展官方模板解析与离线切片检查，A1、A1 mini、P1S、X1 Carbon 的 0.4 mm PLA 官方切片与独立文件检查已在 Mac 执行通过。相应硬件发送仍待现场验证。

| 路线 | 当前范围 |
| --- | --- |
| 官方 Studio，由 Codex 操作界面 | Agent 打开具体切片包，核对机型、板型、材料与发送选项，使用 PrintLab 的批准与单次预约记录，点击一次发送后读回设备。需要当前 Codex 具备桌面控制能力。 |
| 工作台按钮调用本机发送助手 | 中文 Studio 02.08.02.61、X2D、0.4 mm、单主料 PLA/PETG、AMS 左主喷嘴、纹理 PEI、单盘。需要 macOS 14+、用户登录且桌面解锁、辅助功能与屏幕读取权限。 |
| 工作台按钮调用 Bambuddy 队列 | Mac/Windows 共用 HTTP 发送代码，当前接入 A1、A1 mini、P1S、X1 Carbon 的 AMS 路线。需绑定 `bambuddy_queue`、读回正确机型、可用存储卡、IDLE 与具体材料；文件、排队、启动及异常对账使用原任务记录。软件模拟已通过，实际设备接受与首层待现场验证。 |
| 历史原生 MCP 发送 | 发布首版未提供可执行客户端。来源和独立安装边界见 DEPENDENCIES.md。 |

## 独立离线检查

安装程序独立下载 bambu-printer-mcp 1.1.33。工作台预检和官方 Studio 预约通过公开 MCP 文件检查接口核对相同 SHA-256 与盘号；不会传入设备凭据、调用发送工具或启动打印。PrintLab 自身的官方模板、载料及温度检查继续执行。检查成功只证明文件检查通过，仍须核验实时设备、材料、授权及发送助手。

## 准备一次具体打印

1. Codex 根据当前版本、选定材料、板型、喷嘴和机器生成切片包，保存模型和切片 SHA。
2. 展示真实模型、关键尺寸、分盘、材料映射、预计耗时与用量。
3. 使用者确认打印这一版，并确认打印板清洁空置。当前流程校验 30 分钟有效期。
4. 使用 `printlab approve --help`、`printlab submit --help` 确认当前参数。`submit` 默认预检，真实执行需要明确 `--execute`。
5. 发送后使用任务 ID 读回设备，核对实际出料和首层，再等待完成与实物检查。出现超时或回执不明时先对账。

## 设置工作台发送助手

在仓库根目录运行以下命令。`build` 将专用助手安装到本机 `/Applications`，需要 Swift 命令行工具及相应目录写入权限。

```bash
./Harness/bin/printlab studio-bridge build
./Harness/bin/printlab studio-bridge capability
```

使用者选择启用系统权限后，再运行 `./Harness/bin/printlab studio-bridge permissions`，按 macOS 提示授予专用助手权限。随后重跑 `capability` 检查实际状态。`Runtime/config.json` 的 `studio_printer_name` 必须与 Studio 设备名一致。Agent 应读取窗口中的准确名称，并核对 Studio 所选设备与目标设备的序列号。Bambuddy 中的别名可能不同，不能直接代填。缺少名称时，`capability` 会报告配置缺项。

任务超出支持范围时，按具体提示核对并使用官方 Studio 界面工作流。首次配置完成后，使用者仍需对实际设备、材料与打印结果进行验证。

## 远程使用

默认服务仅监听本机 127.0.0.1。需要私人远程访问时，可自行配置 Tailscale 并把自己的地址写入 `tailscale_ip`，再重启服务。本机已登录、未锁屏与实体清板条件仍适用。请在可信私人网络使用工作台，连接规则在 `Harness/serve.py` 中。

连接模式与手机/电脑/Agent 的具体路径见 [连接与控制指南](CONNECTIONS.md)。

## 配置跨平台队列路线

先使用 `workspace profiles --model 机型` 找到实际官方预设，解析机型、工艺和材料配置后切片。单喷嘴的 `extruder_mapping` 使用实际固件喷嘴 0；AMS 槽位按现场读回映射。映射还需包含已确认的材料、颜色、料卷关联与 `routing_verified`，完整字段查询当前 CLI 与实际切片。

准备队列任务时明确设置 `mapping.transport` 为 `bambuddy_queue`。已有官方 Studio 包保留其绑定，转换通道时重新准备任务和具体批准。Bambuddy 写入凭据需能上传文件、维护队列并启动任务。工作台按钮运行同一 `submit`，先上传、读回唯一队列项，再发送一次启动请求。超时保留回执并对账。

设备报告 IDLE、存储卡可用仅证明当前前提。签名或固件拒绝须依据实际返回诊断，首次现场验收记录固件、网络模式、任务、材料和精确设备读回。

机型证据见 [支持范围](MACHINE_SUPPORT.md)，异常处理见 [排障与经验接续](TROUBLESHOOTING.md)。

如果冷启动后的设备卡暂时只显示 `X2D 0.4mm`，助手会在任务名和设备名一致时刷新一次设备卡，然后重新核对完整的双喷嘴信息、料位和打印选项。刷新后仍不匹配会返回错误。错误设备、错误任务和遮挡窗口的系统提示均需先处理。

助手通过本次请求独有的回执确认执行结果。缺少回执、启动异常或发送结果未知时，先核对设备和工作台记录。未知的发送结果保留在记录中，禁止自动再次发送。
